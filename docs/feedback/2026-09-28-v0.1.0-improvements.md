## 1. 과제(task) 관리가 없음 — 가장 중요

**문제**

- 한 세션이 여러 종류의 과제를 맡는데, 이걸 관리하는 기능이 없습니다.
- 보드에 남는 건 두 가지뿐입니다.
  - main이 sub에게 마지막으로 보낸 지시 1건 (Team 탭의 "last order"). 새 지시를 보내면 이전 지시는 사라집니다.
  - ledger의 claim. 어느 과제에서 나온 claim인지는 연결되지 않습니다.
- 대기, 진행, 검토, 막힘, 완료 상태를 알려면 대화 로그를 직접 읽어야 합니다.

**개선안**

- `.agentsemble/tasks.jsonl`을 ledger와 같은 방식(추가만 하는 파일)으로 둡니다.
  ```json
  {"kind":"task","id":"T-12","role":"engine","brief":"SSIM 미탐 감소","status":"queued","at":"..."}
  {"kind":"status","id":"T-12","status":"doing","by":"engine","at":"..."}
  {"kind":"link","id":"T-12","commits":["3f2a1c"],"claims":["C-7"]}
  ```
- 상태 흐름: `queued → doing → review → done`, 그리고 `blocked`
- main이 `/ops task add ...`로 과제를 만들고 sub가 상태를 바꿉니다. `SendMessage`로 보내는 brief에 과제 id를 붙입니다.
- 보드에는 역할별 칸반으로 보여줍니다. 과제를 누르면 brief → 커밋 → claim → verdict가 한 줄로 이어집니다.

## 2. Team 화면에 계층과 최근 작업을 같이

**문제**

- 계층은 Team 탭에, 최근 작업은 Sessions 탭에 따로 있습니다.
- "누가 누구 밑에서 지금 뭘 하나"를 보려면 두 탭을 오가야 합니다.

**개선안**

Team 탭 하나에서 계층 트리를 그리고, 노드마다 지금 상태를 붙입니다.

```
main  ● moving  · 현재 과제: 검출 v2 승격 검토
 │    최근: engine 결과 검증 중 (pytest 38 passed) · 2분 전
 ├─ engine  ● busy    · T-12 "SSIM 미탐 감소" (doing)
 │    최근: Edit image_diff_ssim_v2.py → Bash pytest test_v2/unit
 │    받은 지시: "v2 SSIM 임계값 재조정…" · 14:02
 ├─ ui      ○ waiting · T-13 "대시보드 필터" (review)
 │    최근: 커밋 3f2a1c · main에 보고함
 └─ ops     ◌ stopped · 대기 과제 없음
```

- 노드마다 보여줄 것: 역할과 상태, 현재 과제, 최근 작업 2~3개, 마지막 지시·보고 시각
- 보고가 오래 없는 sub가 한눈에 보이게 합니다.
- 과제 칸을 뺀 나머지는 지금 `/api/board` 데이터(`team.subs[].order`, `sessions[].steps`, `phase`)로 바로 만들 수 있습니다.
- Sessions 탭은 상세 화면(과거 세션 포함, 대화 전체)으로 남기고, Team 노드를 누르면 그쪽으로 넘어갑니다.

## 3. Session / Tools / Team 구분이 모호함

**문제**

- 탭이 사용자가 묻는 질문이 아니라 데이터 종류 기준으로 나뉘어 있습니다.
- "ui 역할에 빠진 도구가 있나"를 보려면 Tools 탭으로 옮겨야 합니다.
- 한 역할 폴더에서 연 과거 세션(재시작, `/resume`)이 전부 같은 비중으로 나열됩니다.

**개선안**

- 역할 노드에 도구 누락 표시를 바로 붙입니다(`missing: taste`, `+ extra`). Tools 탭은 상세 표로만 씁니다.
- 역할마다 활성 세션 하나를 정하고, 나머지는 기록으로 접어둡니다.

## 4. 한 폴더 안에서 동작 — 반영함

**문제**

- 레포 옆에 `<repo>-engine`, `<repo>-ui`, `<repo>-ops`, `agentsemble-board` 폴더가 따로 생겼습니다.

**반영한 것**

- agentsemble이 만드는 모든 것을 main 체크아웃의 `.agentsemble/` 아래에 둡니다.
  ```
  <repo>/.agentsemble/
    wt/<role>/      역할별 worktree
    ledger.jsonl    builder/verifier 장부
    board/          보드 Docker 파일 (compose.yml, .env)
  ```
- `.git/info/exclude`에 `/.agentsemble/`를 넣어서 git 변경 목록에 잡히지 않게 했습니다.
- 기존 방식(`../<repo>-<role>`)과 기존 `ops/ledger.jsonl`도 계속 읽힙니다.
- 팀 해체: 역할마다 `git worktree remove`를 한 뒤 `.agentsemble/`와 `agents.json`을 지웁니다.

**고친 파일**

- `bin/lib/agents.mjs`: `.agentsemble/wt/<role>` 경로 허용, 테스트 2개 추가
- `bin/setup.mjs`: 제외 목록에 `/.agentsemble/` 추가
- `bin/ledger.mjs`: 기본 위치를 `.agentsemble/ledger.jsonl`로 변경. 기존 `ops/ledger.jsonl`이 있으면 그걸 계속 사용
- `agents.schema.json`, `skills/agentsemble/SKILL.md`: 설명 갱신

**확인**

- setup을 다시 돌려서 `.agentsemble/wt/{engine,ui,ops}`만 생기고 형제 폴더는 0개인 것을 확인했습니다.
- git 변경 개수는 41개(기존 40개 + `agents.json`)로, `.agentsemble/`는 잡히지 않습니다.

**남은 문제**

- worktree가 레포 안에 있어서, main에서 전체 검색이나 테스트 자동 탐색을 하면 worktree 사본까지 잡힙니다. 스킬 문서에 주의 문구를 넣었습니다.

## 5. 세션 창을 사람이 직접 열어야 함 — 반영함

**문제**

- 역할마다 터미널을 열고 `cd`, `claude`, `/rename`을 직접 해야 했습니다.

**반영한 것**

- `claude -n <역할>`로 시작할 때 이름을 붙입니다. `/rename`과 같은 효과이고, 보드에도 이름이 잡히는 것을 확인했습니다.
- setup 출력 안내를 `cd "<dir>" && claude -n <role>`로 바꿨습니다.
- 스킬 문서에 추가: 사용자가 요청하면 Windows Terminal 창 하나에 역할별 탭을 연다.
  ```
  wt -w agentsemble nt --title <role> -d "<dir>" claude -n <role> ; nt ...
  ```

**남은 문제**

- 새 폴더를 처음 열 때 뜨는 신뢰 확인은 사람이 눌러야 합니다.
- 지금 대화하는 세션이 레포 밖에서 돌고 있으면 main 창도 새로 열어야 합니다.

## 6. 보드 Docker 실행 — 반영함, 재테스트 전

**문제**

- 보드는 세션 로그 폴더를 호스트 절대경로 기준으로 찾습니다. 그래서 Linux 컨테이너 안에서는 로그를 찾지 못합니다.
- 회사 SSL 프록시 때문에 컨테이너 빌드 중 `apk`/`apt` 설치가 실패합니다.

**반영한 것**

- `bin/board-docker.mjs up | down | logs [--port N]` 명령을 추가했습니다.
  - `.agentsemble/board/`에 `compose.yml`과 `.env`를 만들고 `docker compose up -d --build`를 실행합니다.
- `docker/Dockerfile`: git이 이미 들어 있는 `node:24` 이미지를 써서 패키지를 설치하지 않습니다.
- `docker/entrypoint.mjs`: 호스트 경로 기준 로그 폴더를 컨테이너 경로 이름으로 연결합니다. 로그 폴더가 아직 없어도 미리 연결해 두어서, 새 세션이 재시작 없이 보드에 뜹니다.
- 마운트는 레포, `~/.claude/projects`, `~/.claude/sessions` 모두 읽기 전용입니다.
- 포트는 호스트 `127.0.0.1`에만 엽니다.

**남은 것**

- 이전 구조(형제 폴더)에서는 Docker 보드가 동작하는 것을 확인했습니다.
- 새 구조(`.agentsemble/`)에서는 Docker Desktop 엔진이 뜨지 않아서(exit 4) 아직 띄워보지 못했습니다.

## 7. 보드 CPU 부하 — 일부 반영

**문제**

- 보드 페이지가 2초마다 `/api/board`를 호출하고, 그때마다 `git status`를 실행합니다.
- Docker 안에서는 git 인덱스에 Windows 기준 파일 정보가 들어 있고 마운트가 읽기 전용이라, 매번 파일 내용을 다시 읽어 비교합니다.
- 호출 1번에 약 1.6초가 걸려서 2초 주기의 대부분을 차지했습니다. WSL VM과 보안 에이전트 CPU가 같이 올라갔습니다.

**반영한 것**

- 컨테이너 git 설정에 `core.checkStat=minimal`, `core.trustctime=false`, `core.autocrlf=true`를 넣었습니다.
- 호출 시간이 약 1.6초에서 약 0.65초로 줄었습니다.
- 스킬 문서에 "안 볼 때는 탭을 닫으라"는 안내를 넣었습니다.

**남은 개선**

- 폴링 주기 설정 기능 (지금은 `board.html`에 2초로 고정)
- `git status` 결과 캐시 (예: 30초)
- 탭이 백그라운드에 있으면 폴링 멈추기

## 8. 전체 CLI 세션의 skill/plugin 관리 — 미구현

**문제**

- agentsemble은 자기가 만든 worktree 세션의 도구만 관리합니다.
- 다른 프로젝트 폴더에서 연 CLI 세션이 어떤 skill과 plugin을 쓰고 있는지는 보이지 않습니다.

**개선안**

- 모든 세션을 대상으로 폴더별 켜진 plugin(`enabledPlugins`), 프로젝트 skill(`.claude/skills`), 실제 호출 횟수를 모아서 보여줍니다.
- 세션 로그를 작업 폴더별로 집계하는 기존 사내 도구가 있어서, 거기에 붙이면 됩니다.

## 9. 커밋을 강제하지 않기 — 반영함

**문제**

- 스킬 문서가 `agents.json` 커밋을 필수 단계로 안내했습니다.
- 커밋 안 된 변경이 있어도 경고 없이 worktree를 만들어서, sub는 옛날 코드로 작업하게 됩니다.

**반영한 것**

- 커밋은 사용자가 동의할 때만 하도록 바꿨습니다. setup은 커밋 없이도 동작합니다.
- setup이 커밋 안 된 변경을 감지해서 경고합니다.
  ```
  ! main checkout has 20 uncommitted change(s); new worktrees start from HEAD and will not see them
  ```
- 스킬 문서: 변경이 몇 개인지 알려주고 먼저 커밋할지 묻게 했습니다. 대신 커밋하지는 않습니다.

## 10. 한글 경로에서 setup이 죽는 문제 — 반영함

**문제**

- Node 24.14.1의 `fs.cpSync`가 Windows에서 복사 대상 경로에 한글이 있으면 오류 메시지 없이 프로세스를 끝냅니다(exit 127).
- `setup.mjs --all`이 첫 worktree만 만들고 스킬 복사 단계에서 멈췄습니다.

**반영한 것**

- `bin/setup.mjs`에서 `cpSync` 대신 `copyFileSync`로 재귀 복사하는 함수(`copyTree`)를 씁니다.
- 자체 테스트 120개가 모두 통과했습니다(`node test/run.mjs`).
